# Project scope

## Mission

Explore and, only where technically supported and permitted, build original tools that could enable community-hosted multiplayer experiences for a future game release.

## Current stage

Pre-development. This repository has no game source, game assets, official integration details, compatibility layer, or runnable client/server. Public technical information and applicable terms must be evaluated before game-specific implementation.

## In scope now

- Project documentation, contributor onboarding, and original architecture proposals.
- Research based on public and attributable sources, with uncertainty recorded.
- General-purpose, game-independent experiments that do not reproduce third-party code or rely on undocumented game behavior.
- Developer workflow and community processes.

## Out of scope

- Redistributing game files, proprietary assets, leaked code, or extracted content.
- Circumventing access controls, platform protections, or anti-cheat systems.
- Claiming compatibility or promising features without verifiable support.
- Copying code, distinctive product designs, assets, tools, or documentation from another multiplayer project.
- Representing the project as official or affiliated with the game publisher.

## Scope gate for game-specific work

Before accepting a game-specific implementation proposal, maintainers should record:

1. The public source for the relevant technical interface and its version/date.
2. The permitted integration and distribution model, reviewed against applicable terms.
3. The data and assets involved, their provenance, and whether contributors or users must supply them themselves.
4. A security and privacy review appropriate to the feature.
5. A decision record explaining why the work is supportable and what remains uncertain.

If any of these points cannot be established, keep the work at the proposal or game-independent research stage.
