# Architecture Decision Records

Store significant technical decisions here using sequential filenames, for example `0001-record-template.md`.

Each record should include:

- **Status:** proposed, accepted, superseded, or rejected.
- **Date:** when the decision was made.
- **Context:** the need, constraints, and evidence.
- **Options:** credible alternatives considered.
- **Decision:** what was selected and why.
- **Consequences:** benefits, costs, and follow-up work.

Keep proposals open for discussion until there is enough evidence to decide. Do not present speculative choices as implemented architecture.
